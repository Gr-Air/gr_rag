# 招商银行数据中台项目总结

> 本文档总结[[招商银行]][[数据中台]]项目的建设成果、经验教训与后续演进方向。

## 建设成果

项目历时 11 个月，完成指标平台、标签平台、数据服务三块核心能力建设，
累计接入 78 个源系统，沉淀指标 2400 余个、标签 1300 余个。

| 能力模块 | 关键产出 | 上线时间 |
| --- | --- | --- |
| 指标平台 | 统一指标定义与血缘 | 第 5 个月 |
| 标签平台 | 标签工厂与人群圈选 | 第 8 个月 |
| 数据服务 | 统一查询网关 | 第 11 个月 |

## 架构要点

平台基于[[微服务架构]]构建，查询网关承担统一鉴权、SQL 改写与结果缓存三项职责。
高频指标结果缓存于[[Redis]]，缓存键按"指标 + 维度组合"哈希生成，
缓存失效由上游数据到达事件驱动，避免定时全量刷新造成的峰值。

## 数据链路

| 环节 | 技术方案 | 备注 |
| --- | --- | --- |
| 采集 | 批量抽取 + 变更捕获 | 覆盖结构化与半结构化数据 |
| 加工 | 分层建模 | 原始层/明细层/汇总层/应用层 |
| 服务 | 统一查询网关 | 支持 JDBC 与 HTTP 两种协议 |
| 监控 | 链路埋点 | 覆盖数据时效与质量规则 |

## 经验教训

1. 指标口径必须在建设初期冻结，否则后期返工成本极高；
2. 数据服务网关需要预留降级开关，大促期间可关闭非核心查询；
3. 血缘关系应自动采集而非人工维护，人工维护的覆盖率不足 40%；
4. 跨部门协作需要固定的例会节奏与明确的接口人。

## 后续演进

- 引入数据质量规则引擎，实现异常自动拦截；
- 指标定义与业务术语库打通，支持自然语言检索；
- 逐步开放数据服务给分行自助使用，配套权限与配额管理；
- 探索将知识库问答接入数据服务网关，降低用数门槛。
