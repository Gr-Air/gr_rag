# 中国银行核心系统需求规格说明书

> 本文档定义[[中国银行]]核心系统改造的功能需求、性能需求与接口约束，作为开发与验收依据。

## 范围说明

本次改造覆盖存款、贷款、支付结算三大业务域，涉及 42 个交易码，
存量外围系统通过适配层接入，改造期间要求业务不中断。

## 功能需求

### 存款业务

支持活期、定期、通知存款三类账户的开户、销户、冻结与解冻，
交易需支持冲正与红蓝字处理，所有账务变动必须生成凭证。

### 贷款业务

支持等额本息、等额本金、先息后本三种还款方式，
试算结果需与核心账务系统保持一致，误差容忍度为分。

### 支付结算

接入大额、小额、网联三条清算通道，支持批量代发与代扣，
单笔交易响应时间要求不超过 500ms，批量任务按窗口排期执行。

## 性能需求

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 联机交易平均响应 | ≤ 200ms | 不含网络传输 |
| 联机交易峰值 TPS | 8000 | 促销日峰值 |
| 批量任务窗口 | ≤ 4 小时 | 日终批处理 |
| 系统可用性 | 99.99% | 年度统计 |

## 技术约束

1. 数据库须使用集中式关系型数据库，保留原有事务模型；
2. 缓存统一使用[[Redis]]，禁止业务代码直连数据库缓存表；
3. 异步解耦统一走[[Kafka]]，消息必须支持幂等消费；
4. 所有对外接口需提供版本号与兼容策略。

## 数据一致性

核心账务采用强一致性事务；外围查询链路允许最终一致，时延容忍 5 秒。
跨系统一致性通过[[Kafka]]可靠投递 + 定时对账任务共同保障，
对账差异需生成差错工单并支持人工核销。
