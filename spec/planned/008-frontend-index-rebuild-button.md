# Spec 008: 前端增加全量索引构建入口

> 创建日期：2026-06-11
> 状态：**planned**
> 关联 Issue：`[FEATURE] 前端提供一键全量索引重建按钮`

---

## 1. 动机

当前全量索引重建只能通过命令行 `node scripts/buildIndex.cjs` 执行，对非开发人员不友好。用户修改文档后需要通过终端手动重建，缺乏可视化入口和进度反馈。

**现状**：
- 首页已展示"索引状态"卡片（就绪/构建中）
- 没有 API 路由可以触发索引重建
- 没有管理类页面

**目标**：在前端提供一键触发全量索引构建的能力，并给予进度反馈。

---

## 2. 行为契约

### 2.1 正常路径

```
用户点击"重建索引" → API 触发构建 → SSE 流式推送进度 → 构建完成刷新状态
```

**触发流程**：

```
[首页 "索引状态" 卡片]
  ├── 状态显示：就绪 / 构建中 / 未就绪
  ├── [重建索引] 按钮（仅在非构建中时可用）
  └── 点击后 → POST /api/index/rebuild
                  ├── 返回 SSE 流
                  ├── event: progress → { stage, message, percent }
                  └── event: done → { success, docCount, termCount }
```

### 2.2 边界条件

| 输入 | 预期输出 |
|------|---------|
| 索引正在构建中，再次点击 | 按钮置灰 + toast 提示"索引构建进行中" |
| LanceDB 目录不存在 | 正常执行全量构建，创建新索引 |
| DASHSCOPE_API_KEY 未配置 | 返回错误 + 提示"请先配置 Embedding API Key" |
| 构建过程中出错 | SSE 推送 error 事件 + 按钮恢复可用 |
| 文档数量为 0 | 正常构建空索引 |

### 2.3 错误处理

| 异常场景 | 预期行为 |
|----------|---------|
| API Key 缺失 | 返回 400 + 明确提示 |
| 构建脚本异常退出 | 捕获 stderr，SSE 推送错误信息 |
| 构建超时（超过 5 分钟） | 自动终止子进程，推送 timeout 事件 |

---

## 3. 验收标准

- [ ] 首页"索引状态"卡片旁新增"重建索引"按钮
- [ ] 新增 POST `/api/index/rebuild` 路由，以 SSE 流推送构建进度
- [ ] 构建进行中按钮置灰 + 显示进度
- [ ] 构建完成后更新页面索引状态为"就绪"
- [ ] 未配置 API Key 时给出明确错误提示

---

## 4. 方案设计

### 4.1 新增 API 路由

`src/app/api/index/rebuild/route.ts` — POST + SSE 流式响应：

```
调用 child_process.spawn('node', ['scripts/buildIndex.cjs'], { env })
  → 捕获 stdout 解析进度
  → SSE 流式推送给前端
```

或者直接复用 `scripts/buildIndex.cjs` 中的逻辑，提取为可 import 的模块。

### 4.2 前端改动

`src/app/page.tsx` — 在"索引状态"卡片中添加按钮：

```tsx
<button
  onClick={triggerRebuild}
  disabled={isBuilding}
  className="..."
>
  {isBuilding ? '构建中...' : '重建索引'}
</button>
```

需要新增状态管理：
- `isBuilding` — 是否正在构建
- `buildProgress` — 当前进度 `{ stage, percent }`

### 4.3 实现锚点（计划）

| 文件 | 函数/区域 | 变更类型 |
|------|----------|---------|
| `src/app/api/index/rebuild/route.ts` | POST handler + SSE | 新增 |
| `src/app/page.tsx` | 索引状态卡片区域 | 修改 |
| `src/lib/indexManager.ts` | 可能新增 `triggerBuild()` | 修改 |

### 4.4 备选方案：管理页面

除了在首页加按钮，也可以新建 `src/app/admin/page.tsx` 管理页面，集中管理以下操作：
- 全量索引重建
- 增量索引更新
- 结构化数据库重建
- 索引状态详情

然后在 `layout.tsx` 导航栏增加"管理"入口。首页按钮方案更轻量，管理页面方案更完整，两者可兼容：首页提供快捷入口，管理页提供完整功能。

## 5. 兼容影响

### 5.1 公开 API 变更

| API | 变更类型 | 迁移方式 |
|-----|---------|---------|
| `POST /api/index/rebuild` | 新增 | 新建路由 |

### 5.2 数据格式变更

无。不涉及索引格式变更，仅新增触发方式。

### 5.3 下游调用方

| 调用方 | 是否受影响 | 说明 |
|--------|-----------|---------|
| `src/app/page.tsx` | ✅ 待修改 | 新增按钮 + SSE 消费 |
| 命令行脚本 | ❌ 不受影响 | `buildIndex.cjs` 保持独立可运行 |

---

## 6. 降级策略

- 命令行 `node scripts/buildIndex.cjs` 作为始终可用的降级方案
- 如果 SSE 连接断开，后台构建继续运行，前端可通过轮询 `/api/stats` 检测完成状态
- 新增路由不影响现有功能

---

## 7. 待讨论

1. **是否需要确认弹窗**？全量重建耗时较长（取决于文档数量），建议加二次确认
2. **是否需要增量构建按钮**？可以同时提供"增量更新"入口，但会引入额外的复杂度
3. **是否需要管理页面**？如果后续管理功能增多，建议提前规划管理页面，而非仅在首页加按钮
4. **构建进度解析策略**：`buildIndex.cjs` 的 stdout 已有阶段标识（`[1/4]`、`[2/4]` 等），可以直接解析
