# Spec 001: RAG 语义缓存（Redis Embedding 匹配）

> 创建日期：2026-07-05
> 状态：planned | **in-progress** | implemented | archived
> 关联 Issue：`[FEAT] RAG 语义缓存 - Redis Embedding 匹配`
> 关联分支：feat/rag-semantic-cache

---

## 1. 动机

当前 RAG 系统每次查询都需要完整执行检索→生成流程，即使是相同或相似的查询也会重复调用 LLM，造成不必要的 token 消耗和响应延迟。

本变更通过 Redis 向量索引实现语义缓存：
- 相同或相似查询（embedding 相似度 ≥ 0.9）直接返回缓存结果
- 响应时间从秒级降至毫秒级
- 大幅降低重复查询的 token 消耗

---

## 2. 行为契约

### 2.1 正常路径

| 输入 | 预期输出 |
|------|---------|
| 用户提问 "项目经理是谁" | 首次查询：正常 RAG 流程，生成回答后写入缓存 |
| 用户提问 "谁是项目经理"（语义相似） | 缓存命中：直接返回缓存的回答，响应时间 < 100ms |
| 用户提问 "详细说说项目管理计划"（语义不同） | 缓存未命中：正常 RAG 流程 |

### 2.2 边界条件

| 输入 | 预期输出 |
|------|---------|
| Redis 未启动 | 降级为正常流程，不报错 |
| 索引更新后 | 缓存失效，重新生成回答 |
| 追问（"还有呢？"） | 跳过缓存，正常 RAG 流程 |
| 查询 embedding 生成失败 | 降级为正常流程 |

### 2.3 错误处理

| 异常场景 | 预期行为 |
|----------|---------|
| Redis 连接失败 | 降级为正常流程，日志记录警告 |
| 向量索引创建失败（已存在） | 忽略错误，继续使用已存在的索引 |
| 缓存数据损坏 | 返回 null，降级为正常流程 |

---

## 3. 验收标准

- [ ] 相同查询第二次请求时命中缓存，响应时间 < 100ms
- [ ] 语义相似查询（embedding 相似度 ≥ 0.9）命中同一缓存
- [ ] 语义不同查询（embedding 相似度 < 0.9）不命中缓存
- [ ] Redis 不可用时自动降级，不影响正常功能
- [ ] 追问查询不使用缓存
- [ ] 索引更新后缓存失效

## 5. 兼容影响

### 5.1 公开 API 变更

| API | 变更类型 | 迁移方式 |
|-----|---------|---------|
| `/api/chat` | 无破坏性 | 返回结果新增 `cached: boolean` 字段 |

### 5.2 数据格式变更

Redis 存储格式：
- 向量索引：`rag:cache:idx`（HNSW 索引，维度由 `EMBEDDING_DIM` 环境变量决定，COSINE 距离）
- 缓存数据：`rag:cache:data:<id>`（Hash 结构）
  - `embedding` 字段：FLOAT32 little-endian 二进制（packed bytes），非 JSON 字符串；写入与 KNN 查询参数均使用此格式
- 缓存 ID 集合：`rag:cache:ids`（Set 结构）

### 5.3 下游调用方

| 调用方 | 影响 |
|--------|------|
| 前端聊天组件 | 可利用 `cached` 字段显示缓存命中提示 |

---

## 6. 降级策略

- Redis 不可用时：自动跳过缓存，执行正常 RAG 流程
- 向量索引不存在时：自动创建索引（首次访问）
- 缓存查询失败时：返回 null，继续正常流程
